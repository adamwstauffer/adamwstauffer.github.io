# adamwstauffer.github.io

Adam W. Stauffer's personal site: finance and economics teaching, applied AI work, writing, books in
progress, and things built. Live at **https://adamwstauffer.github.io/**.

## What is here

The repository mirrors the sections of the home page.

| Section | Where it lives | Notes |
|---|---|---|
| Home | `index.html` | Hand-written. Intro, links, and one card per item below. |
| Writing | `writing/<slug>.html` | One hand-written page per essay, linked from its card on the home page. First essay: [The doer–reviewer dilemma](https://adamwstauffer.github.io/writing/doer-reviewer-dilemma.html). |
| Books in progress | `index.html` only | Three titles, each marked in progress. No pages yet. |
| Resume, CV, bio | `content/*.md` → `resume.html`, `cv.html`, `bio.html`, `resume.pdf` | Generated by `build.py`; see below. The site is the master copy. |
| Applied AI work | `index.html` only | Links out to [Kumu](https://adamwstauffer.github.io/ai-lms/), the course tutorial site, and the [course materials repo](https://github.com/adamwstauffer/shidler). |
| Builds | `treehouse/index.html` | The treehouse design-and-build showcase, one self-contained page. Greenshoot.org and the food forest are cards only. |

## How it is built

Plain static HTML with no build step for most pages. `.nojekyll` tells GitHub Pages to serve the
files as they are. Every page carries the same small stylesheet inline: one set of color tokens
with light and dark values, Georgia for body text, a system sans for labels and navigation. A new
page copies the tokens from `index.html` rather than inventing its own.

**Resume, CV and bio** are the exception. Their master copies are the Markdown files in `content/`
(`resume.md`, `cv.md`, `bio.md`). Edit those, then run:

```
pip install markdown
python build.py
```

It regenerates `resume.html`, `cv.html`, `bio.html` and, when Chromium or Chrome is on the path,
`resume.pdf`. Commit all of them together so the HTML never drifts from the Markdown.

**Essays** are written as HTML in `writing/`, starting from the previous essay's file so the
header, navigation and footer match. When an essay goes live, its card on the home page links to
it and the "in review" line comes out.

## Publishing

Merging to `main` publishes the site. Work lands on a branch (`feat/<slug>`, `fix/<slug>`) and goes
to `main` through a pull request. The pull request is the moment to see exactly what readers will
see; merging it is the release.

## Conventions

- American English spelling. Quoted titles keep their original spelling.
- External links open in a new tab (`target="_blank" rel="noopener"`); links within the site do not.
- No analytics, no scripts, no third-party assets. Pages work offline once loaded.
- An essay's date is the month it went live.
